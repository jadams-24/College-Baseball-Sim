# College Baseball Sim — project rules

Read this before doing anything. These rules exist because five previous attempts at this engine failed at realism. They are not suggestions.

## What this is
A college baseball simulation engine, built in phases. Long-term it becomes a full program-management game (OOTP-depth on-field sim + CFB-style roster building + facilities). Right now it is a statistical engine that must match real NCAA Division I numbers before anything else is built.

## The two rules
1. **Every sim run prints a realism report against `benchmarks.json`.** Nothing is tuned by watching box scores or by feel. If a number is off, the fix is traced to a rate or a model, not a fudge constant.
2. **Every constant lives in `config/`.** If a number in the code cannot be traced to an entry in `benchmarks.json` (or to a source noted in `PHASE0_NOTES.md`), it is a guess. Guesses are allowed but must be marked `# GUESS` and listed in `GUESSES.md`.

## Phase gates
Phases advance only when the gate passes. Do not build ahead of the current phase.

## Architecture constraints
- **The engine never makes a decision; it asks for one.** Every choice point (lineup, pitching change, steal, bunt, pinch hit, IBB) goes through the controller of the team it belongs to (`engine/control.py`). An AI manager (a `Decider`, e.g. `engine/manager.py`) answers it now; a human answers the same call later. Games are played by a `GameSession` (`engine/game2.py`, 2026-10-06): plate appearances forward, pitch by pitch, with a pause point before every pitch, sim-ahead stops, and save and restore at any pause point (`tests/test_session_determinism.py`).
- **Resumable runs.** `scripts/run_phase5.py` saves each finished season under `runs/<key>/`, the key a hash of everything the seasons read (engine, config, scripts, derived inputs, benchmarks.json; never docs): a restart skips finished seasons and never reuses seasons of other code (owner decision 2026-10-08).
- **Deterministic given a seed, per machine.** Every game and season takes an RNG seed and reproduces exactly on the same machine. Across machines it does not: CPU-dependent floating point (linear algebra and vector math) changes the draws, so CI's run of the report seeds differs from the committed report. CI therefore checks that its own 40-season run passes every gate, and that each gated row's value agrees with the committed report within sampling error (`tests/agreement.py`, `config.phase2.CI_AGREEMENT_Z`), not verdict for verdict.
  - Watch item, to fix before Phase 12 (shared leagues and saves need it): make the simulation deterministic across machines.
  - Keyed random streams (2026-10-06): the engine and each team's AI manager draw from their own counter-based streams, positioned by plate appearance and decision point (`engine/rng.py` KeyedStream). Who answers a decision, or how many draws an earlier answer used, never moves a later draw. Changing to these streams changed every seed's results once; all reports were regenerated on 2026-10-06.
- **In-game management and sim controls** (product requirement, owner decision 2026-10-06).
  - The user can manage a game pitch by pitch. Before any pitch they can call a steal, hit-and-run, bunt, pitchout, intentional ball or pitching change, or make a mound visit, pinch runner or defensive change. Example that must work: stealing on a 2-0 count.
  - The user can sim ahead at any moment: next at-bat, half inning, full inning, three innings or end of game. While simming, the AI manager makes the user's decisions, then hands control back at the stopping point.
  - Human and AI decisions resolve with the same outcome probabilities. The human gets no better or worse odds than the AI.
  - Steal success depends on count, runner speed, catcher arm and a pitcher hold/time-to-plate rating. There is no pitch-type model: the play-by-play has no pitch types, so one would be guesswork; fitting by count captures the real pitch mix in each count.
  - Pitch types are a possible future display layer that never changes outcomes, unless real pitch-type data becomes available. Pitch calling by the user is out of scope.
  - Steal attempts by the AI manager depend on game state (score, inning, outs, count), fitted from the play-by-play.
- **Box score** (2026-10-09, `engine/boxscore.py`): runs, runs batted in, stolen bases, caught stealing per batter and the pitchers' win, loss, save and hold, for every game, scored by the NCAA rules (Rule 10-9, 10-11, 10-25, 10-26; holds are not an NCAA statistic). Bookkeeping only: it draws nothing (`config.box.ENABLED` off plays identical games). Players carry an empty `year` field for Phase 8.
- **Engine is headless.** No UI code in the engine package. Reports are markdown/HTML written to `reports/`.
- **Game UI prototype (2026-10-08, `app/`).** A browser-playable single game on the session interface: a connector, a thin web API and a static frontend (`app/README.md`). The connector works by snapshot and replay (the session is snapshotted before a pitch, the human's controller raises when the human must be consulted, the snapshot is restored and the pitch re-run with the answer as an order), because the session pauses only before a pitch while the engine asks its decisions between two pauses. This is a prototype workaround: the final engine should pause natively at decision points, a change that goes through the engine session with full gates (Phase 12). Engine, config and benchmarks are untouched by the app. Workflow (owner decision 2026-10-08): `ui-prototype` is the single live branch (Render auto-deploys every push; the app tests and the API-vs-engine equality tests run before every push), engine PRs merged to `main` are merged into it promptly, and it returns to `main` through a PR at checkpoints; CI runs only the app tests for changes under `app/` (`.github/workflows/app.yml`), the full gates for everything else. The visual system (2026-10-09, owner decision: the recruiting canvas's system is the app-wide standard for desktop play; `app/README.md`, Design system): Barlow Condensed headings, IBM Plex Sans body, IBM Plex Mono stats; one shared top bar (school, program tabs, date and phase, Advance); cards with header strips centered at 1440px with a side panel; 38px table rows; rating colors as text; status pills; no emoji; 36px buttons. The manager screen (v2, `app/static/v2/`, served at `/`) draws its action menu from the server (`app/menu.py`: only the calls legal now for the user's side, tested against the engine's eligibility rules) and labels the pitcher's bar "pitch count" because the engine has no fatigue state. Dynasty mode (2026-10-08, `app/dynasty.py`): the Phase 7 season driven game by game from the app with the engine's own per-game seeds and the postseason pipeline replayed over recorded results, so a dynasty equals `engine.season.simulate_season` for the same seed (`tests/test_app_dynasty.py`); Year 1 ends after Omaha with an offseason placeholder. The advance loop (2026-10-09) runs the regular season day by day over registered world steps (`app/world_steps.py`: name, cadence, order, a run function returning auto-pause events; `d1_games` now, the Phase 8–11 steps as documented placeholders gated on the Phase 9 calendar), so later phases register theirs without changing the loop. One calendar (`app/calendar.py`, 2026-10-09): engine date 0 is the Monday of the opening week, anchored on `config.phase6.SEASON_START`, the opening day read from the schedule; every displayed date and every world step's calendar gate goes through it. The team picker and hub show each sim team's real school and report card from `data/schools/` (PR #17), Omaha Contender regraded from the dynasty's draw; display only. World sims run as background jobs: a week is minutes and a season over an hour on the free tier (`reports/dynasty_latency.md`).
- **Data is committed.** Scraped NCAA tables and play-by-play go in `data/` and are committed, not re-fetched each session. Record the fetch date and source URL in `data/README.md`.

## Stack
- Python 3.11+, `numpy`, `pandas`, `pytest`. Add dependencies only when needed and pin them in `requirements.txt`.
- Tests in `tests/`. Each phase gate is a pytest test that loads `benchmarks.json` and fails outside tolerance. CI runs them on every push.

## Workflow
- Work on a branch, open a PR. The PR description includes the realism report for the current phase.
- Never edit `benchmarks.json` values without a new source and a note in `PHASE0_NOTES.md`.
- When a gate fails, report why before proposing a fix. Do not silently widen a tolerance.
- **Merging** (owner rule 2026-10-09): merge any PR whose CI passes every gate and agrees with the committed reports, without waiting for the owner, and report what merged. Ask the owner only when a gate fails, a tolerance or benchmark would change, or a design decision is needed.
- **No-outcome-change PRs** (bookkeeping, speed): prove every game is bit-identical with `scripts/check_log_identity.py` (300 games, same machine, before and after) and keep `tests/test_boxscore.py`'s on/off comparison green.
- **Speed work keeps every draw** (speed pass 2026-10-09): only rewrites that compute the same floating-point operations in the same order (numpy's exp, log, matrix products and LAPACK solve stay numpy calls; elementwise arithmetic and in-order sums may move to plain floats), proven by `tests/test_speed.py` and the log hash. Report-only accumulators sit behind `config.diagnostics.RECORD` (on for every report and gate; off for dynasty play: same games, same stats, about 20% faster).
- **Drift check on the calibrated maps** (owner rule 2026-10-08). Any PR that changes engine behavior runs `scripts/check_drift.py` (a short run on its own seeds): the strength map (recovered against drawn ratings: slope 1, curvature 0, tier means), the home edge and the Phase 5 pitch chain (events by count against the data). A check beyond 2 SE is re-solved in the same PR (`scripts/solve_phase2_game_scale.py --warm`, `scripts/solve_phase5_chain.py --warm`), and `reports/drift_check.md` goes in the PR. No silent drift across PRs.
